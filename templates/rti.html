RTI Resiliency & Recovery GUIDANCE

Eventhouse / KQL Database

Data replication requires continuous export configured on the primary KQL Database to Azure Storage, with the secondary KQL Database ingesting from the same storage.

  • Schema sync via definition export/import
  • Data sync via continuous export + follower databases
  • RPO: Depends on continuous export lag
  • RTO: Minutes

KQL Querysets

Query definitions are synced via the Fabric Items API. Querysets reference KQL Databases which must be independently replicated.

  • Definition sync via export/import
  • Database references remapped automatically
  • RPO: Near-zero (definition-based)
  • RTO: Seconds

Eventstreams

Eventstream definitions are synced with destination artifact remapping. Source connections (Event Hub, Kafka) may require manual re-authentication.

  • Definition sync with destination remapping
  • Source connections need credential update
  • RPO: Real-time (depends on source lag)
  • RTO: Seconds (with pre-configured sources)
